# Qci/Qbv 时间扰动处理实验

## 组会汇报初版

### 1. 研究问题

本实验比较三种周期性 ST 流处理方案在时间扰动和异常帧条件下的能力。

1. **Qbv-only**。只使用出口 TAS 门控。
2. **Full-Qci+Qbv**。使用 Stream Filter、Stream Gate、Flow Meter 和 Qbv。
3. **Clipped-Qci+Qbv**。裁剪 PSFP 流门控表，保留 Stream Filter、Flow Meter，并增加时间戳、周期、序号、Deadline 和 MaxQueueDelay 判断，再由 Qbv 完成出口调度。

Qbv主要回答帧什么时候可以发送。Qci和扩展入口准入逻辑回答帧是否属于合法流、是否仍然值得发送，以及是否会造成后续积压。

### 2. 三种方案的能力总览

符号含义如下。

- **可以**。方案有明确机制处理该情况。
- **部分可以**。方案能够延迟、隔离或被动丢弃，但不能准确判断业务价值。
- **不能**。方案没有对应状态或判断依据。

| 情况 | Qbv-only | Full-Qci+Qbv | Clipped-Qci+Qbv |
|---|---|---|---|
| 正常准时帧 | 可以 | 可以 | 可以 |
| 轻微早到 | 部分可以，通常等待下一个合法窗口 | 可以通过 Stream Gate 约束入口 | 可以按 EarlyTolerance 判断 |
| 严重早到 | 部分可以，可能长期缓存 | 可以过滤或隔离，效果取决于门控配置 | 可以超过提前容差后丢弃 |
| 轻微晚到 | 部分可以，可能等待下一个窗口 | 部分可以，标准门控不等于截止时间判断 | 可以预测下一窗口是否能完成 |
| 无法在当前窗口完成的晚到帧 | 不能主动判断，只能等待 | 部分可以，可能继续等待或被门控阻断 | 可以按预计完成时间处理 |
| 超过 Deadline 的旧帧 | 不能 | 标准 Qci 本身没有完整业务时限判断 | 可以主动丢弃 |
| 未注册流 | 不能识别 | 可以由 Stream Filter 拒绝 | 可以由 Stream Filter 拒绝 |
| 错误入口、VLAN、PCP 或流标识 | 不能按流判断 | 可以过滤 | 可以过滤 |
| 速率超限 | 不能主动监管 | 可以由 Flow Meter 监管 | 可以由 Flow Meter 监管 |
| 突发插帧 | 可能进入 ST 队列并占用窗口 | 可以通过流量监管限制，不能保证识别每个插入序号 | 可以结合 Flow Meter 和序号判断 |
| 重复序号 | 不能识别 | 当前实现没有序号过滤 | 可以由序号状态判断 |
| 丢帧和序号缺口 | 不能识别 | 当前实现没有重排状态机 | 可以发现序号缺口，但当前尚未实现 ReorderTimeout |
| 乱序到达 | 不能判断业务顺序 | 当前实现不维护序号顺序 | 可以发现顺序异常，但仍需要重排缓存和超时 |
| 持续过载 | 队列持续增长，可能溢出 | 可以在入口限制过载帧 | 可以主动丢弃过期或预计无法按时完成的帧 |
| 队列等待时间超限 | 不能判断 | 需要额外配置或扩展 | 可以使用 MaxQueueDelay |
| 多交换机 GCL 相位差 | 依赖正确的逐跳配置 | 依赖门控配置和同步 | 可以使用容差处理，但仍需要同步误差模型 |
| 链路容量不足 | 不能解决 | 不能增加链路容量 | 不能增加容量，只能优先保留新鲜帧 |

### 3. 多帧时间扰动场景

下面的场景以同一条周期性 ST 流中的 `f1`、`f2`、`f3` 为例。判断重点是帧之间的先后关系、等待关系和相互影响，不把异常简化为单个帧独立处理。

#### 3.1 早到帧

**场景 E1，f1 在 PSFP 门打开前到达。**

- Qbv-only 没有入口 PSFP 门。f1 会继续进入网络，之后由出口 Qbv 决定是否等待合法发送窗口。
- Full-Qci+Qbv 的门关闭时，f1 可能被门控阻断、缓存或丢弃，具体取决于 Stream Gate 的实现和配置。
- Clipped-Qci+Qbv 不依赖流门控表。时间判断模块比较 f1 的预计到达时间和实际到达时间，轻微早到可以等待，超过 EarlyTolerance 可以丢弃。

**场景 E2，f1、f2 到达顺序反转，f2 先于 f1 到达。**

- Qbv-only 按到达和队列状态处理，可能先发送 f2，无法判断 f1 是否缺失、延迟还是仍在路上。
- Full-Qci+Qbv 可以确认两帧属于合法流，但当前实现没有序号状态机，因此不能保证 f1 一定先于 f2 交付。
- Clipped-Qci+Qbv 可以通过序号发现 f2 先到并进入 GAP 或乱序状态，理论上应暂存 f2 等待 f1。当前实现还没有 ReorderTimeout，不能完整验证等待超时和释放逻辑。

**场景 E3，f1 正在到达或等待处理时，f2 也提前到达。**

- 如果 f1、f2 属于同一周期，f2 可能成为额外帧或插入帧。Qbv-only 可能让两帧同时占用 ST 队列和后续窗口。
- Full-Qci+Qbv 可以用 Flow Meter 限制这次短时突发，但仅靠流门控不能判断 f2 是否是合法的下一序号。
- Clipped-Qci+Qbv 同时检查周期、序号和 Flow Meter。若 f2 是重复或超出每周期预期数量的帧，可以过滤。若 f2 属于下一周期，则需要根据序号和时间戳区分正常提前到达与插帧。

**场景 E4，f1、f2、f3 连续多个周期都提前到达。**

- Qbv-only 的等待帧可能连续占用缓存，后续正常帧可能出现队头阻塞。
- Full-Qci+Qbv 可以限制入口通过节奏，但如果门控窗口和流量计配置过宽，早到帧仍可能进入后续队列。
- Clipped-Qci+Qbv 可以按每帧提前量判断，并在缓存增长前丢弃超过容差的帧。

#### 3.2 晚到帧

**场景 L1，f1 在 PSFP 门关闭之后到达。**

- Qbv-only 没有入口门判断。f1 可能进入出口队列，等待下一个 Qbv 窗口。
- Full-Qci+Qbv 的门关闭时，f1 可能被阻断、缓存或丢弃，是否丢弃取决于门控配置。标准门控本身不等于 Deadline 判断。
- Clipped-Qci+Qbv 计算下一可用窗口和预计完成时间。若完成时间超过 Deadline 或 MaxQueueDelay，则主动丢弃，否则等待下一合法窗口。

**场景 L2，f1、f2 到达顺序反转，晚到的 f1 在 f2 之后到达。**

- Qbv-only 可能先发送 f2，无法确认序号缺口，也可能因为 f1 占用后续窗口而继续积压。
- Full-Qci+Qbv 可以限制两帧是否进入入口，但当前实现不保证序号顺序，因此可能出现乱序交付或等待行为不一致。
- Clipped-Qci+Qbv 可以识别 f1 和 f2 的序号关系。若 f2 已经到达，系统需要决定缓存 f2 等待 f1，还是在 ReorderTimeout 后放行 f2。当前实验只实现了序号和时效判断，没有完整重排超时模块。

**场景 L3，f1 晚到但 f2 尚未到达。**

- Qbv-only 可能让 f1 等待下一个窗口。f1 的等待会占用队列位置，f2 到达后可能排在 f1 后面，形成队头阻塞。
- Full-Qci+Qbv 可以通过入口门控和 Flow Meter 限制继续进入的帧数，但不能仅依靠标准门控判断 f1 是否已经失去业务价值。
- Clipped-Qci+Qbv 先判断 f1 的预计完成时间。若 f1 已不可按时完成，则丢弃 f1，为后续 f2 释放队列和窗口。若 f1 仍然满足 Deadline，则保留 f1，并让 Qbv 在下一合法窗口发送。

**场景 L4，f1、f2、f3 连续多个周期晚到。**

- Qbv-only 会把每周期无法完成的帧推迟到后续窗口，队列和尾部时延持续增加。
- Full-Qci+Qbv 可以通过门控和流量监管减少进入队列的帧，但没有额外时效状态时，可能继续保留已经过期的帧。
- Clipped-Qci+Qbv 可以逐帧检查 Deadline、MaxQueueDelay 和预计完成时间，优先删除旧帧，保护后续新鲜帧。

#### 3.3 多帧与同步误差组合

**场景 T1，f1 早到，f2 准时到达。** 需要判断 f1 是否占用 f2 的合法窗口，以及 f1 是否应等待或丢弃。

**场景 T2，f1 晚到，f2 准时到达。** 需要判断 f1 是否在 f2 前形成队头阻塞，以及丢弃 f1 后 f2 是否能按时发送。

**场景 T3，f1、f2 在不同交换机上受到方向相反的时钟偏差。** 一跳可能认为 f1 过早，下一跳可能认为 f1 过晚。三种方案都需要同步误差、GCL 相位和传播时延配置，Clipped-Qci 只能通过容差和预计完成时间降低误判。

### 4. 多帧丢失、乱序和重复场景

#### 4.1 丢帧和序号缺口

**场景 M1，f1、f2、f3 中 f2 丢失，f1 和 f3 正常到达。**

- Qbv-only 不知道 f2 是否丢失，可能直接发送 f3，也可能因队列等待继续延迟。
- Full-Qci+Qbv 当前没有序号状态机，不能确认 f2 已经丢失。
- Clipped-Qci+Qbv 可以发现 f3 相对 f1 的序号缺口，但应等待 ReorderTimeout 后才能确认 f2 丢失。该超时模块当前尚未实现。

**场景 M2，f1、f2、f3、f4 中连续丢失 f2 和 f3。** 需要区分短暂延迟和连续丢失，避免无限等待不存在的帧。

**场景 M3，上一周期的 f1 丢失，下一周期的 f2 正常到达。** 需要避免把跨周期的正常 f2 错误判断为乱序，也需要确认上一周期缺口是否已经超时。

#### 4.2 乱序

**场景 O1，f2 先到，f1 后到。** 这是相邻序号乱序，重点观察是否缓存 f2、是否先交付 f2，以及 f1 到达后是否会重复处理。

**场景 O2，f1 在本周期晚到，f2 已经进入下一周期。** 这是跨窗口乱序，旧 f1 可能已经超过 Deadline，不应为了恢复顺序而阻塞新鲜 f2。

**场景 O3，f1、f2、f3 经过多交换机后到达顺序改变。** 需要记录每一跳的排队时间，区分入口乱序、逐跳门控等待和路径差异。

#### 4.3 重复和重放

**场景 D1，f1、f2、f2、f3 在同一周期到达。** 重复的 f2 可能占用一个额外发送机会。

**场景 D2，f1、f2、f3 到达后，旧的 f1 再次到达。** 这是跨周期重放，不能只依据流标识判断合法性。

**场景 D3，重复 f2 的时间戳改变但序号不变。** 需要同时比较序号、周期和时间戳。

Qbv-only无法区分这些情况。Full-Qci可以识别流和速率，但当前实现不保证序号去重。Clipped-Qci需要保存每条流的最近序号和周期状态。

### 5. 多帧插入、非法流和突发场景

**场景 I1，同一周期正常到达 f1，额外插入 x1。** Qbv-only 可能把 x1 当作普通 ST 帧发送。Full-Qci 可以由 Flow Meter 限制额外帧，但同一合法流中的 x1 可能仍通过。Clipped-Qci 可以结合周期计数、序号和 Flow Meter 丢弃 x1。

**场景 I2，同一周期到达 f1、x1、x2、f2。** 需要观察两个插入帧是否挤占 f2 的窗口，以及 f2 是否被推迟到下一周期。

**场景 I3，f1、f2 属于合法流，x1 使用未注册流标识。** Full-Qci 和 Clipped-Qci 可以由 Stream Filter 拒绝，Qbv-only 无法按流身份区分。

**场景 I4，x1 使用合法流标识但错误 PCP、VLAN 或入口端口。** 需要区分流过滤失败和时间准入失败，不能只记录为普通丢帧。

**场景 I5，f1、f2 正常到达，同时出现短时突发 x1、x2、x3。** 需要观察 Flow Meter 的突发阈值、队列峰值和正常帧误丢率。

### 6. 多帧队列和链路容量场景

**场景 Q1，每周期只有 f1。** 三种方案都可以在低负载下完成合法发送，主要观察基础时延。

**场景 Q2，每周期到达 f1、f2，而一个 Qbv ST 窗口只能完成一帧。** Qbv-only 会把其中一帧推迟。Full-Qci 和 Clipped-Qci 需要决定入口保留哪一帧以及是否丢弃过期帧。

**场景 Q3，f1、f2、f3 连续多个周期到达，服务能力低于到达速率。** Qbv-only 队列持续增长。Full-Qci 可以用门控和 Flow Meter 限制入口。Clipped-Qci 还可以根据预计等待时间优先丢弃旧帧。

**场景 Q4，旧帧 f1 已经在队列中，新的 f2 到达。** 需要比较保留 f1 等待发送和丢弃 f1 保护 f2 两种策略。

**场景 Q5，ST 流与 NST 背景流同时增加负载。** 需要观察 ST 队列、NST 队列、出口门控和缓存溢出之间的相互影响。

**场景 Q6，f1、f2、f3 经过多个交换机。** 需要分别记录每一跳队列峰值、每一跳等待时间和最终端到端时延，不能只看最后一个交换机的队列。

### 7. 非时间异常和同步误差场景

1. **S1，f1、f2 使用不同交换机时钟，偏差小于容差。** 观察是否仍能保持顺序和截止时间。
2. **S2，f1、f2 的时钟偏差超过容差。** 观察正常帧是否被误判为早到或晚到。
3. **S3，f1 在 switch1 的窗口内到达，但在 switch2 的窗口关闭后到达。** 观察逐跳门控是否造成额外等待或丢弃。
4. **S4，f1、f2 的传播时延不同。** 观察路径差异是否引起乱序。
5. **S5，f1、f2、f3 受到同步误差和突发插帧的组合影响。** 这是后续多跳压力实验需要重点补充的组合场景。

### 8. 当前实验实现口径

为了在组会上准确表述，当前代码和方案能力应分开说明。

- Qbv-only已经实现出口传输门控和ST队列调度。
- Full-Qci+Qbv已经使用INET的Stream Filter、Periodic Gate和Single Rate Two Color Meter。
- 当前Full-Qci实现还没有完整的序号状态机、重复帧过滤和ReorderTimeout。
- Clipped-Qci+Qbv已经实现时间准入、插帧过滤、Flow Meter式突发限制、Deadline和MaxQueueDelay策略。
- 当前Clipped-Qci准入模块仍位于发送端应用边界，还不是独立的交换机入口模块。
- 当前实验没有加入独立的多跳时钟偏差、传播时延和多随机种子重复。

### 9. 组会结论

1. Qbv-only能保证合法出口窗口，但不知道帧是否过期、重复、缺失或属于异常突发。
2. Full-Qci+Qbv能解决流识别、入口门控和速率监管问题，但标准Qci不能自动完成序号连续性和逐帧Deadline判断。
3. Clipped-Qci+Qbv通过时间戳、周期、序号、Deadline和MaxQueueDelay补充了裁剪流门控表后的时间状态判断，更适合控制最大时延和保证新鲜帧优先。
4. 三种方案都不能增加链路容量，也不能恢复已经丢失的帧。差异主要体现在异常帧进入网络的位置、是否能够识别业务时效，以及是否能够在队列溢出前主动丢弃。
5. 下一步重点是把Clipped-Qci准入模块移动到交换机入口，加入ReorderTimeout、多跳同步误差和多随机种子重复实验。
