# Qci/Qbv 时间扰动处理实验

## 组会汇报初版

### 1. 研究问题

本实验比较三种周期性 ST 流处理方案在时间扰动和异常帧条件下的能力。

1. **Qbv-only**。只使用出口 TAS 门控。
2. **Full-Qci+Qbv**。使用 Stream Filter、Stream Gate、Flow Meter 和 Qbv。
3. **Clipped-Qci+Qbv**。目标设计裁剪 PSFP 入口流门控表，保留 Stream Filter 和 Flow Meter，在交换机入口加入时间与序号准入，在出口复用 Qbv。当前发送端原型的覆盖范围见第 8 节，详细设计见第 9 节。

Qbv主要回答帧什么时候可以发送。Qci和扩展入口准入逻辑回答帧是否属于合法流、是否仍然值得发送，以及是否会造成后续积压。

### 2. 三种方案的能力总览

下表比较机制与设计能力。裁剪方案列按第 9 节的目标设计填写，实验覆盖见第 8 节。

- **可以**。方案有明确机制处理该情况。
- **部分可以**。方案能够延迟、隔离或被动丢弃，但不能准确判断业务价值。
- **不能**。方案没有对应状态或判断依据。

| 情况 | Qbv-only | Full-Qci+Qbv | Clipped-Qci+Qbv |
|---|---|---|---|
| 正常准时帧 | 可以 | 可以 | 可以 |
| 轻微早到 | 部分可以，入队后按出口窗口发送 | 按实际到达时刻判定，入口门关时丢弃 | 可以按 EarlyTolerance 判断并限时暂存 |
| 严重早到 | 部分可以，仍按出口窗口处理 | 入口门关闭时丢弃，落入其他开门窗口时可能通过 | 可以超过提前容差后丢弃 |
| 轻微晚到 | 部分可以，窗口余量不足时等待下一窗口 | 门开时可通过入口过滤，门关时丢弃 | 可以预测当前或后续窗口是否能完成 |
| 无法在当前窗口完成的晚到帧 | 不能主动判断，只能等待 | 部分可以，可能继续等待或被门控阻断 | 可以按预计完成时间处理 |
| 超过 Deadline 的旧帧 | 不能 | 标准 Qci 本身没有完整业务时限判断 | 可以主动丢弃 |
| 未注册 ST 流 | 无逐流准入限制 | 可配置为拒绝，当前实验有默认旁路 | 拒绝未匹配的 ST 候选帧 |
| 错误入口、VLAN、PCP 或流标识 | 无逐流准入限制 | 可按配置匹配的字段过滤 | 按流规则校验匹配字段 |
| 速率超限 | 不能主动监管 | 可以由 Flow Meter 监管 | 可以由 Flow Meter 监管 |
| 突发插帧 | 可能进入 ST 队列并占用窗口 | 可以通过流量监管限制，不能保证识别每个插入序号 | 可以结合 Flow Meter 和序号判断 |
| 重复序号 | 不能识别 | 当前实现没有序号过滤 | 可以由序号状态判断 |
| 丢帧和序号缺口 | 不能识别 | 当前实现没有重排状态机 | 设计上按序号检测缺口，超时后跳过 |
| 乱序到达 | 不能判断业务顺序 | 当前实现不维护序号顺序 | 设计上用有界重排缓存恢复顺序 |
| 持续过载 | 队列持续增长，可能溢出 | 可以在入口限制过载帧 | 可以主动丢弃过期或预计无法按时完成的帧 |
| 队列等待时间超限 | 不能判断 | 需要额外配置或扩展 | 可以使用 MaxQueueDelay |
| 多交换机 GCL 相位差 | 依赖正确的逐跳配置 | 依赖门控配置和同步 | 可以使用容差处理，但仍需要同步误差模型 |
| 链路容量不足 | 不能解决 | 不能增加链路容量 | 不能增加容量，只能优先保留新鲜帧 |

### 3. 多帧时间扰动场景

下面的场景以同一条周期性 ST 流中的 `f1`、`f2`、`f3` 为例，编号代表业务预期顺序。到达时刻统一按交换机完整收帧、交给入口处理的时刻定义。裁剪方案的处理动作对应第 9 节的设计。

#### 3.1 早到帧

**场景 E1，f1 在 PSFP 门打开前到达。**

- Qbv-only 没有入口 PSFP 门。f1 会继续进入网络，之后由出口 Qbv 决定是否等待合法发送窗口。
- Full-Qci+Qbv 中，只要 f1 匹配受控 ST 流且到达时入口流门关闭，当前 INET 配置就会在入口丢弃 f1。若 f1 落在上一周期的开门窗口，仍可能通过。 [INET 入口过滤模块](https://doc.omnetpp.org/inet/api-current/neddoc/inet.linklayer.ieee8021q.SimpleIeee8021qFilter.html)
- Clipped-Qci+Qbv 不依赖流门控表。时间判断模块比较 f1 的预计到达时间和实际到达时间，轻微早到可以等待，超过 EarlyTolerance 可以丢弃。

**场景 E2，f1、f2 到达顺序反转，f2 先于 f1 到达。**

- Qbv-only 按到达和队列状态处理，可能先发送 f2，无法判断 f1 是否缺失、延迟还是仍在路上。
- Full-Qci+Qbv 可以确认两帧属于合法流，但当前实现没有序号状态机，因此不能保证 f1 一定先于 f2 交付。
- 裁剪方案按序号发现 f1 缺口。在 f2 仍能满足时限的前提下暂存 f2，等待补齐缺口或超时释放。

**场景 E3，f1 尚在处理或等待发送时，f2 也提前到达。**

- Qbv-only 可能让两帧同时占用 ST 队列和后续窗口。对同一条串行入口链路，此处指两帧在交换机内的处理或排队时间重叠。
- Full-Qci+Qbv 可以用 Flow Meter 限制这次短时突发，但仅靠流门控不能判断 f2 是否是合法的下一序号。
- Clipped-Qci+Qbv 同时检查周期、序号和 Flow Meter。若 f2 是重复或超出每周期预期数量的帧，可以过滤。若 f2 属于下一周期，则需要根据序号和时间戳区分正常提前到达与插帧。

**场景 E4，f1、f2、f3 连续多个周期都提前到达。**

- Qbv-only 的等待帧可能连续占用缓存，后续正常帧可能出现队头阻塞。
- Full-Qci+Qbv 可以限制入口通过节奏，但如果门控窗口和流量计配置过宽，早到帧仍可能进入后续队列。
- Clipped-Qci+Qbv 可以按每帧提前量判断，并在缓存增长前丢弃超过容差的帧。

#### 3.2 晚到帧

**场景 L1，f1 在 PSFP 门关闭之后到达。**

- Qbv-only 没有入口门判断。f1 可能进入出口队列，等待下一个 Qbv 窗口。
- 若受控 ST 帧 f1 到达时入口流门仍关闭，当前 Full-Qci 仿真会丢弃它。若 f1 晚到至下一个开门窗口，流门仍可能放行。
- 裁剪方案查找可用的 Qbv 窗口。预计交付超过 Deadline 或预计等待超过 MaxQueueDelay 时丢弃，其余可行帧进入合法窗口。

**场景 L2，f1、f2 到达顺序反转，晚到的 f1 在 f2 之后到达。**

- Qbv-only 可能先发送 f2，无法确认序号缺口，也可能因为 f1 占用后续窗口而继续积压。
- Full-Qci+Qbv 可以限制两帧是否进入入口，但当前实现不保证序号顺序，因此可能出现乱序交付或等待行为不一致。
- 裁剪方案暂存 f2，给 f1 留出有限的补到时间。f1 补到后按顺序重新检验两帧的调度可行性。f1 过期或缺口超时时，跳过 f1 并重新检查 f2。

**场景 L3，f1 晚到但 f2 尚未到达。**

- Qbv-only 可能让 f1 等待下一个窗口。f1 的等待会占用队列位置，f2 到达后可能排在 f1 后面，形成队头阻塞。
- Full-Qci+Qbv 可以通过入口门控和 Flow Meter 限制继续进入的帧数，但不能仅依靠标准门控判断 f1 是否已经失去业务价值。
- Clipped-Qci+Qbv 先判断 f1 的预计完成时间。若 f1 已不可按时完成，则丢弃 f1，为后续 f2 释放队列和窗口。若 f1 仍然满足 Deadline，则保留 f1，并让 Qbv 在下一合法窗口发送。

**场景 L4，f1、f2、f3 连续多个周期晚到。**

- Qbv-only 会把无法在当前窗口发完的帧推迟到后续窗口。若到达速率持续高于窗口服务能力，队列和尾部时延会继续增加。
- Full-Qci+Qbv 可以通过门控和流量监管减少进入队列的帧，但没有额外时效状态时，可能继续保留已经过期的帧。
- Clipped-Qci+Qbv 可以逐帧检查 Deadline、MaxQueueDelay 和预计完成时间，优先删除旧帧，保护后续新鲜帧。

#### 3.3 多帧与同步误差组合

**场景 T1，f1 早到，f2 准时到达。** 需要判断 f1 是否占用 f2 的合法窗口，以及 f1 是否应等待或丢弃。

**场景 T2，f1 晚到，f2 准时到达。** 需要判断 f1 是否在 f2 前形成队头阻塞，以及丢弃 f1 后 f2 是否能按时发送。

**场景 T3，f1、f2 在不同交换机上受到方向相反的时钟偏差。** 一跳可能认为 f1 过早，下一跳可能认为 f1 过晚。三种方案都需要同步误差、GCL 相位和传播时延配置，Clipped-Qci 只能通过容差和预计完成时间降低误判。

### 4. 多帧丢失、乱序和重复场景

#### 4.1 丢帧和序号缺口

**场景 M1，f1、f2、f3 中 f2 丢失，f1 和 f3 正常到达。**

- Qbv-only 不知道 f2 是否丢失，可能直接发送 f3，也可能因队列等待继续延迟。
- Full-Qci+Qbv 当前没有序号状态机，不能确认 f2 已经丢失。
- 裁剪方案在收到 f3 时记录 f2 的缺口。等待达到规定上限时记录超时缺口，并重新检查 f3 的时限。超时表示系统停止等待，物理丢失和超时后补到由实验真值区分。

**场景 M2，f1、f2、f3、f4 中连续丢失 f2 和 f3。** 需要区分短暂延迟和连续丢失，避免无限等待不存在的帧。

**场景 M3，上一周期的 f1 丢失，下一周期的 f2 正常到达。** 需要避免把跨周期的正常 f2 错误判断为乱序，也需要确认上一周期缺口是否已经超时。

#### 4.2 乱序

**场景 O1，f2 先到，f1 后到。** 这是相邻序号乱序，重点观察是否缓存 f2、是否先交付 f2，以及 f1 到达后是否会重复处理。

**场景 O2，f1 在本周期晚到，f2 已经进入下一周期。** 这是跨窗口乱序，旧 f1 可能已经超过 Deadline，不应为了恢复顺序而阻塞新鲜 f2。

**场景 O3，f1、f2、f3 经过多交换机后到达顺序改变。** 需要记录每一跳的排队时间，区分入口乱序、逐跳门控等待和路径差异。

#### 4.3 重复和重放

**场景 D1，f1、f2、f2、f3 在同一周期到达。** 重复的 f2 可能占用一个额外发送机会。

**场景 D2，f1、f2、f3 到达后，旧的 f1 再次到达。** 这是跨周期重放，不能只依据流标识判断合法性。

**场景 D3，重复 f2 的时间戳改变但序号不变。** 需要同时比较序号、周期和时间戳。

Qbv-only无法区分这些情况。Full-Qci可以识别流和速率，但当前实现不保证序号去重。Clipped-Qci需要保存每条流的最近序号和周期状态。

### 5. 多帧插入、非法流和突发场景

**场景 I1，同一周期正常到达 f1，额外插入 x1。** Qbv-only 可能把 x1 当作普通 ST 帧发送。Full-Qci 可以由 Flow Meter 限制额外帧，但同一合法流中的 x1 可能仍通过。Clipped-Qci 可以结合周期计数、序号和 Flow Meter 丢弃 x1。

**场景 I2，同一周期到达 f1、x1、x2、f2。** 需要观察两个插入帧是否挤占 f2 的窗口，以及 f2 是否被推迟到下一周期。

**场景 I3，f1、f2 属于合法流，x1 使用未注册流标识。** Full-Qci 的处理取决于默认路径配置。裁剪方案明确拒绝未匹配的 ST 候选帧，并单独保留合法 NST 的转发路径。Qbv-only 无逐流准入限制。

**场景 I4，x1 使用合法流标识但错误 PCP、VLAN 或入口端口。** 需要区分流过滤失败和时间准入失败，不能只记录为普通丢帧。

**场景 I5，f1、f2 正常到达，同时出现短时突发 x1、x2、x3。** 需要观察 Flow Meter 的突发阈值、队列峰值和正常帧误丢率。

### 6. 多帧队列和链路容量场景

**场景 Q1，每周期只有 f1。** 三种方案都可以在低负载下完成合法发送，主要观察基础时延。

**场景 Q2，每周期到达 f1、f2，而一个 Qbv ST 窗口只能完成一帧。** Qbv-only 会把其中一帧推迟。Full-Qci 和 Clipped-Qci 需要决定入口保留哪一帧以及是否丢弃过期帧。

**场景 Q3，f1、f2、f3 连续多个周期到达，服务能力低于到达速率。** Qbv-only 队列持续增长。Full-Qci 可以用门控和 Flow Meter 限制入口。Clipped-Qci 还可以根据预计等待时间优先丢弃旧帧。

**场景 Q4，旧帧 f1 已经在队列中，新的 f2 到达。** 需要比较保留 f1 等待发送和丢弃 f1 保护 f2 两种策略。

**场景 Q5，ST 流与 NST 背景流同时增加负载。** 需要观察 ST 队列、NST 队列、出口门控和缓存溢出之间的相互影响。

**场景 Q6，f1、f2、f3 经过多个交换机。** 需要分别记录每一跳队列峰值、每一跳等待时间和最终端到端时延，不能只看最后一个交换机的队列。

### 7. 多跳同步误差场景

1. **S1，f1、f2 经多台交换机转发，交换机间偏差在容差内。** 观察是否仍能保持顺序和截止时间。
2. **S2，f1、f2 经多台交换机转发，交换机间偏差超过容差。** 观察正常帧是否被误判为早到或晚到。
3. **S3，f1 在 switch1 的窗口内到达，但在 switch2 的窗口关闭后到达。** 观察逐跳门控是否造成额外等待或丢弃。
4. **S4，f1、f2 的传播时延不同。** 观察路径差异是否引起乱序。
5. **S5，f1、f2、f3 受到同步误差和突发插帧的组合影响。** 这是后续多跳压力实验需要重点补充的组合场景。

### 8. 当前实验实现口径

- Qbv-only 已实现出口传输门控和 ST 队列调度。
- Full-Qci+Qbv 的受控 ST 路径使用 INET 流分类、PeriodicGate 和 SingleRateTwoColorMeter。当前配置对未匹配流保留默认旁路。
- 裁剪方案的基线预测在发送端应用内运行。它使用注入计划标记识别插帧，再用预计窗口判断指定晚到帧的 Deadline。消融配置可启用每个计划周期的帧数计数，策略与敏感性配置分别试验预计等待上限或早到容差。
- 交换机逐流序号状态机、乱序缓冲、重排超时、真实队列感知、出口过期清理和多跳时钟偏差仍属设计。现有多交换机实验使用串联拓扑验证转发与门控。

### 9. Qci（裁剪流门控）+ Qbv 详细实现方案

#### 9.1 模块接线与职责

**入口收帧 → 流识别与过滤 → Flow Meter → 时间与序号准入 → 出口 ST 队列 → Qbv TAS**

交换机保留逐流识别、帧长检查和令牌桶监管。只移除 ST 路径上基于入口流门控表的周期性开关。自定义准入模块位于流量监管之后、出口排队之前，读取同步入口时间和业务帧序号，访问目标出口的 GCL 和队列状态。出口仍按流量类别使用既有的 TAS，合法 NST 走自己的路径。作为第一版，单交换机先接入一条 ST 流。 [INET 流量监管示例](https://inet.omnetpp.org/docs/showcases/tsn/streamfiltering/tokenbucket/doc/index.html) · [INET 时间感知整形示例](https://inet.omnetpp.org/docs/showcases/tsn/trafficshaping/timeawareshaper/doc/index.html)

#### 9.2 每条流需要的配置和状态

| 配置或状态 | 用途 |
|---|---|
| 流标识、入口、VLAN、PCP、最大帧长、目标出口 | 确认帧属于已登记的 ST 流，并选定出口队列 |
| 起始序号、起始周期、周期 $P$、每周期预期帧数与各帧计划偏移 | 将业务序号映射到计划周期和预计入口到达时刻 $t_{\mathrm{exp}}$，使提前到达的下一周期帧归入正确周期 |
| EarlyTolerance、LateTolerance、Deadline、MaxQueueDelay | 分别用于提前容差、晚到分类、绝对交付时限与本站累计等待上限 |
| 令牌补充速率、桶深、每周期帧数上限 | 分别约束长期速率、短期突发与业务周期配额 |
| 下一个预期序号、有限序号窗口、重排缓冲、最近已处理序号、缺口定时器 | 暂存先到的后续帧，跟踪补到、超时、重复与旧序号 |
| 出口门表、链路速率、在发帧和排队帧、下游时延预算 | 预测本交换机发送时段与最终交付时刻 |

实验第一版使用可直接比较的单调序号。有限位宽序号需要按同一流会话处理回绕，发送端重启后按新的会话基准重新初始化。序号窗口外的跳变不能直接推进预期序号。

#### 9.3 入口如何决定放行、暂存或丢弃

1. **检查流和配额。** 校验入口、流标识及长度，再应用 Flow Meter。读取序号与所属周期，丢弃重复帧、已跳过的旧帧及超出接收窗口的异常序号。同周期允许多帧时，按该周期内的合法序号位置和帧数配额判断，合法的 f2 可以继续进入准入。暂存成功的帧同时占用本周期配额和重排缓冲，重复到达的副本不重复占用。
2. **判定早到和晚到。** 以同步入口收帧时刻 $t_{\mathrm{rx}}$ 比较 $t_{\mathrm{exp}}$。若 $t_{\mathrm{rx}} < t_{\mathrm{exp}}-\mathrm{EarlyTolerance}$，丢弃超容差帧。容差内早到帧可以等到自身最早可用的周期窗口。若 $t_{\mathrm{rx}} > t_{\mathrm{exp}}+\mathrm{LateTolerance}$，标记为晚到，继续进行可行性检查。预计时限适用于所有入队帧。
3. **检查出口是否还有可用时段。** 从目标出口的 GCL 查找第一个足以发完整帧的 ST 时间段，计入在发帧、保护带、排在前面的有效帧和缓冲释放时刻。得到预计发送开始时刻 $t_{\mathrm{start}}$ 和完成时刻 $t_{\mathrm{finish}}$。当前窗口装不下时继续检查后续窗口，搜索在时限耗尽时结束。
4. **按两个条件做准入。** 要求 $t_{\mathrm{start}}-t_{\mathrm{rx}}\le\mathrm{MaxQueueDelay}$，以及 $t_{\mathrm{finish}}+B_{\mathrm{downstream}}\le D_f$。前者包含入口暂存和出口排队，后者包含下游剩余时延预算。第一版沿用按计划时刻计龄的实验口径，以源端计划时刻加 Deadline 得到绝对截止时刻 $D_f$。多跳沿用同一个 $D_f$，各跳按自己的 GCL 和剩余路径预算更新预测。
5. **处理序号反转。** f2 先到时，若仍有可行发送机会，就按序号暂存。缺口等待截止取“首次发现缺口的时刻 + ReorderTimeout”与“保证后续帧仍能调度的最晚释放时刻”中较早者。f1 补到时一并重算两帧的出口时段，优先按序交付。f1 若无法再满足时限，或按序发送会使 f2 失约，则按新鲜帧优先策略跳过 f1。等待到期时重新检查并释放仍可按时交付的帧。后续新到帧不能延长已有缺口定时器。
6. **出队前复核。** 已入队和尚未开始发送的帧，在出口取队头时重新核对剩余窗口与时限。淘汰过期队头后继续检查下一帧。正在发送的帧继续发送。如果仍有效的帧总需求超过窗口容量，允许按时限和队列容量丢弃，并记录实际原因。

缓冲区设定每流及每出口容量上限。永久跳过的序号需要写回序号状态，晚到旧帧据此丢弃。受控序号在缓冲区内已存在时只保留首份通过校验的副本。时间与序号检查能识别超期、重复和大幅跳号。未经身份校验时，使用有效序号且时间合理的插入帧可能占用真实帧的序号位置。

#### 9.4 用 f1、f2、f3 走一遍

| 帧之间发生的情况 | 准入和调度动作 | 对后续帧的影响 |
|---|---|---|
| f1 在参考 PSFP 门开启前到达，f2 准时 | f1 提前量在容差内时等待自己的 Qbv 窗口。超容差时丢弃 f1 | f2 按自身时限评估，入口等候占用计入缓冲上限 |
| f2 早到先于 f1，或 f1 晚到落在 f2 后面 | 暂存 f2。若 f1 及时补到且两帧都能按序按时发送，就先 f1 后 f2。否则跳过 f1 或按时限释放 f2 | 保住 f2 的发送机会。缺口关闭后到达的旧 f1 被拒绝 |
| f2 提前到达时 f1 仍在排队 | 同周期按允许的帧数和序号位置检查，跨周期按 f2 自己的窗口检查 | 合法 f2 的预计开始时刻包含前方仍有效的 f1。已经过期的 f1 可在出队前清理 |
| f1 在参考 PSFP 门关闭后到达，且早于 f2 | 如果实际出口窗口还有足够余量，就用当前窗口。余量不足时检查后续窗口。等不起则立即丢弃 f1 | f2 到达时根据 f1 的保留或丢弃结果重算可用时段 |
| f1、f3 到达，f2 缺失 | 暂存 f3 并开启缺口计时。f2 补到时重算顺序。超时后跳过 f2 | f3 在还来得及的情况下交付。后补 f2 计为超时后到达 |
| f1、插入帧 x1、f2 连续到达 | x1 超出周期配额、重复序号或触发监管时丢弃。x1 完全符合规则时仍可能通过 | 统计 f2 是否因为窗口占用、缓存上限或监管耗尽受到影响 |

举例以 $1\,\mathrm{ms}$ 周期、$[900,1000)\,\mathrm{\mu s}$ 和 $[1900,2000)\,\mathrm{\mu s}$ 两个 ST 窗口说明。f1、f2 的计划时刻分别为 $900$ 和 $1900\,\mathrm{\mu s}$，f2 在 $1840\,\mathrm{\mu s}$ 先到，f1 在 $1870\,\mathrm{\mu s}$ 补到。假设早到容差为 $100\,\mathrm{\mu s}$，缺口等待上限 $80\,\mathrm{\mu s}$，站内等待上限 $100\,\mathrm{\mu s}$，单帧占用 $10\,\mathrm{\mu s}$，且端口空闲、两帧均通过流量监管。若 Deadline 为 $2\,\mathrm{ms}$，可分别在 $1900$ 和 $1910\,\mathrm{\mu s}$ 发 f1、f2。若 Deadline 为 $1\,\mathrm{ms}$，f1 截止于 $1900\,\mathrm{\mu s}$，而最早在 $1910\,\mathrm{\mu s}$ 发完，因此跳过 f1，f2 可从 $1900\,\mathrm{\mu s}$ 开始发送。这里省略下游传输时延，用于说明准入决策。

#### 9.5 OMNeT++ 接入与验收

1. **把扰动注入与决策分开。** 发送端按配置生成可控的到达顺序和缺失帧，并随帧携带可解析的业务序号。仿真真值仅用于统计。交换机只读它能观察到的流标识、序号、入口时间与出口状态。用 NED 接入自定义入口模块，复用 INET 的分类、监管和出口 TAS。在 ST 出口队列增加发送前检查，向准入模块提供队列状态，并记录过期清理结果。
2. **先跑单交换机的确定性序列。** 分别注入早到越界、f2 先到、f1 晚到但仍能按序、f1 过期且 f2 可交付、f2 缺口超时、重复帧和连续突发。再加入同一时刻到达、门关闭边界、缓冲上限及三交换机逐跳相位差。三种方案使用相同输入序列和出口配置。
3. **逐帧核对结果。** 记录流、序号、到达与出队时间、各跳等待、丢弃原因和交付顺序。汇报源端发送、有效交付、按原因丢弃和最大队列，同时统计重排成功、超时缺口、正常帧误丢和 Deadline Miss。检查保留下来的同流帧按序出端口，且任何开始发送的帧都能在对应的可用窗口内完成。

### 10. 组会结论

1. Qbv-only能保证合法出口窗口，但不知道帧是否过期、重复、缺失或属于异常突发。
2. Full-Qci+Qbv能解决流识别、入口门控和速率监管问题，但标准Qci不能自动完成序号连续性和逐帧Deadline判断。
3. 裁剪方案的发送端原型已验证时间准入对尾部时延的影响。交换机版设计进一步通过有界重排、出口窗口预测和队头超期清理，处理 f1、f2 相互影响的场景。
4. 三种方案都不能增加链路容量，也不能恢复已经丢失的帧。差异主要体现在异常帧进入网络的位置、是否能够识别业务时效，以及是否能够在队列溢出前主动丢弃。
5. 下一步重点是把Clipped-Qci准入模块移动到交换机入口，加入ReorderTimeout、多跳同步误差和多随机种子重复实验。
