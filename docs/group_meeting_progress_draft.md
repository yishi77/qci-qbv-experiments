# Qci/Qbv 时间扰动处理实验

## 组会汇报初版

### 1. 研究问题

本实验比较三种周期性 ST 流处理方案在时间扰动和异常帧条件下的能力。

1. **Qbv-only**。只使用出口 TAS 门控。
2. **Full-Qci+Qbv**。使用 Stream Filter、Stream Gate、Flow Meter 和 Qbv。
3. **Clipped-Qci+Qbv**。裁剪 PSFP 流门控表，保留 Stream Filter、Flow Meter，并增加时间戳、周期、序号、Deadline 和 MaxQueueDelay 判断，再由 Qbv 完成出口调度。

Qbv主要回答帧什么时候可以发送。Qci和扩展入口准入逻辑回答帧是否属于合法流、是否仍然值得发送，以及是否会造成后续积压。

### 2. 三种方案的能力总览

符号含义如下。

- **可以**。方案有明确机制处理该情况。
- **部分可以**。方案能够延迟、隔离或被动丢弃，但不能准确判断业务价值。
- **不能**。方案没有对应状态或判断依据。

| 情况 | Qbv-only | Full-Qci+Qbv | Clipped-Qci+Qbv |
|---|---|---|---|
| 正常准时帧 | 可以 | 可以 | 可以 |
| 轻微早到 | 部分可以，通常等待下一个合法窗口 | 可以通过 Stream Gate 约束入口 | 可以按 EarlyTolerance 判断 |
| 严重早到 | 部分可以，可能长期缓存 | 可以过滤或隔离，效果取决于门控配置 | 可以超过提前容差后丢弃 |
| 轻微晚到 | 部分可以，可能等待下一个窗口 | 部分可以，标准门控不等于截止时间判断 | 可以预测下一窗口是否能完成 |
| 无法在当前窗口完成的晚到帧 | 不能主动判断，只能等待 | 部分可以，可能继续等待或被门控阻断 | 可以按预计完成时间处理 |
| 超过 Deadline 的旧帧 | 不能 | 标准 Qci 本身没有完整业务时限判断 | 可以主动丢弃 |
| 未注册流 | 不能识别 | 可以由 Stream Filter 拒绝 | 可以由 Stream Filter 拒绝 |
| 错误入口、VLAN、PCP 或流标识 | 不能按流判断 | 可以过滤 | 可以过滤 |
| 速率超限 | 不能主动监管 | 可以由 Flow Meter 监管 | 可以由 Flow Meter 监管 |
| 突发插帧 | 可能进入 ST 队列并占用窗口 | 可以通过流量监管限制，不能保证识别每个插入序号 | 可以结合 Flow Meter 和序号判断 |
| 重复序号 | 不能识别 | 当前实现没有序号过滤 | 可以由序号状态判断 |
| 丢帧和序号缺口 | 不能识别 | 当前实现没有重排状态机 | 可以发现序号缺口，但当前尚未实现 ReorderTimeout |
| 乱序到达 | 不能判断业务顺序 | 当前实现不维护序号顺序 | 可以发现顺序异常，但仍需要重排缓存和超时 |
| 持续过载 | 队列持续增长，可能溢出 | 可以在入口限制过载帧 | 可以主动丢弃过期或预计无法按时完成的帧 |
| 队列等待时间超限 | 不能判断 | 需要额外配置或扩展 | 可以使用 MaxQueueDelay |
| 多交换机 GCL 相位差 | 依赖正确的逐跳配置 | 依赖门控配置和同步 | 可以使用容差处理，但仍需要同步误差模型 |
| 链路容量不足 | 不能解决 | 不能增加链路容量 | 不能增加容量，只能优先保留新鲜帧 |

### 3. 时间扰动的细分情况

#### 3.1 早到帧

早到帧可以继续细分为以下情况。

1. **轻微早到**。帧只比预计时间提前少量时间，仍然可能在本周期合法窗口发送。
2. **超过提前容差**。帧提前量超过允许范围，继续保留会增加缓存占用。
3. **连续早到**。多个周期的帧都提前到达，可能造成早到帧排在正常帧前面。
4. **早到与 NST 竞争**。早到帧提前进入队列，可能挤占其他流的缓存或发送机会。
5. **多跳早到累积**。每一跳都重新等待窗口，等待时间可能逐跳增加。

Qbv-only只能依靠出口门控延迟早到帧。Full-Qci可以使用Stream Gate限制入口通过时间。Clipped-Qci可以比较时间戳和预计到达时间，并根据EarlyTolerance选择等待、隔离或丢弃。

#### 3.2 晚到帧

晚到帧需要区分当前窗口是否还有足够发送时间。

1. **晚到但当前窗口仍能完整发送**。可以直接进入ST队列。
2. **晚到且当前窗口剩余时间不足**。继续发送会跨越关门边界，需要等待下一窗口。
3. **等待一个周期后仍未过期**。帧仍然可能有业务价值，可以继续保留。
4. **预计下一窗口完成后超过Deadline**。帧已经不值得继续占用队列，应主动丢弃。
5. **连续晚到**。每周期都等待下一窗口，容易形成队头阻塞和尾部时延增长。
6. **晚到叠加突发**。晚到帧和插入帧同时出现时，队列增长速度更快。

Qbv-only会把无法及时发送的帧留到下一个窗口。Full-Qci可以依靠门控限制入口，但标准门控不能自动计算每帧的预计完成时间。Clipped-Qci在入口计算下一可用窗口、预计完成时间和Deadline。

#### 3.3 时间漂移和同步误差

1. **固定小幅时钟偏差**。可以通过EarlyTolerance和LateTolerance吸收。
2. **偏差超过容差**。正常帧可能被误判为早到或晚到。
3. **不同交换机偏差方向相反**。一跳放行的帧可能在下一跳被判为不合时序。
4. **GCL基准时间不一致**。各交换机的ST窗口相位错开，可能造成额外等待。
5. **传播时延未计入**。多跳路径中预计完成时间会被低估。

三种方案都不能凭空消除时钟误差。Clipped-Qci可以通过容差和逐跳预计完成时间降低误判，但必须提供同步误差和传播时延模型。

### 4. 丢帧、乱序和重复帧的细分情况

#### 4.1 丢帧

1. **单个序号丢失**。例如序号100之后直接收到102。
2. **连续多个序号丢失**。需要决定等待范围，避免一直等待不存在的帧。
3. **丢帧后续帧正常到达**。后续帧是否交付取决于是否启用重排和超时。
4. **某一跳集中丢帧**。需要定位丢失发生的交换机和入口。
5. **周期边界丢帧**。上一周期最后一帧和下一周期第一帧可能被误判为乱序。

Qbv-only没有序号状态。当前Full-Qci实验也没有加入序号状态机。Clipped-Qci可以根据序号发现缺口，但当前实现还没有ReorderTimeout，因此只能说明发现缺口的能力，不能完整验证等待和超时释放流程。

#### 4.2 乱序

1. **相邻序号交换**。101先到，100后到。
2. **跨窗口乱序**。前一个周期的帧延迟到下一个窗口才到达。
3. **多跳造成的乱序**。不同路径或不同队列的等待时间不同。
4. **乱序帧已经过期**。即使后来到达，也不应继续占用ST窗口。

#### 4.3 重复和重放

1. **同一周期内重复发送**。
2. **网络重传导致的重复帧**。
3. **旧周期帧重放**。
4. **重复序号但时间戳不同**。
5. **时间戳和序号组合不一致**。

Qbv-only无法识别这些情况。Full-Qci的流过滤器可以检查流身份和基本字段，但不能代替序号检查。Clipped-Qci需要维护每条流的最近序号、周期和时间戳状态。

### 5. 插帧、非法帧和流量异常的细分情况

#### 5.1 插帧

1. **同一合法流中每周期多出一帧**。
2. **同一合法流中出现突发多帧**。
3. **插入帧使用重复序号**。
4. **插入帧使用未出现过的新序号**。
5. **插入帧的时间戳与序号不匹配**。
6. **插入帧使用错误PCP、VLAN或入口端口**。

Qbv-only可能让插入帧占用发送窗口。Full-Qci可以用Flow Meter限制突发，并用Stream Filter拒绝未注册流，但同一已注册流内的插入帧仍可能通过。Clipped-Qci需要组合Flow Meter、序号和时间模型。

#### 5.2 流身份和格式异常

1. 未注册StreamID。
2. 错误入口端口。
3. 错误目的端口或VLAN。
4. 错误PCP映射。
5. 超过最大帧长度。
6. FCS、以太网头或协议封装错误。

Stream Filter适合处理流身份和基本字段。帧长、FCS和协议格式检查主要由以太网和协议栈组件完成，不能把这些能力全部归因于Qci时间判断。

### 6. 队列和链路容量的细分情况

1. **单帧低负载**。每周期只有一帧，三种方案通常都能完成发送。
2. **同一周期多帧**。Qbv窗口内可能无法完成全部帧。
3. **短时突发**。队列出现短暂峰值，Flow Meter可以限制入口。
4. **持续过载**。到达速率持续高于ST窗口服务能力，Qbv-only会持续积压。
5. **队列接近容量上限**。需要在入口提前丢弃无业务价值的帧。
6. **队列溢出**。所有方案最终都可能被动丢帧，区别在于是否能在溢出前主动丢弃。
7. **ST与NST竞争**。需要观察ST队列和NST队列之间的影响。
8. **多交换机逐跳积压**。每一跳的等待可能叠加到端到端时延。

Qbv-only主要在出口处理队列，因此过载时容易出现高平均队列和高尾部时延。Full-Qci可以在入口限制流量。Clipped-Qci可以进一步判断帧是否已经过期或预计无法按时完成，从而优先释放旧帧。

### 7. 当前实验实现口径

为了在组会上准确表述，当前代码和方案能力应分开说明。

- Qbv-only已经实现出口传输门控和ST队列调度。
- Full-Qci+Qbv已经使用INET的Stream Filter、Periodic Gate和Single Rate Two Color Meter。
- 当前Full-Qci实现还没有完整的序号状态机、重复帧过滤和ReorderTimeout。
- Clipped-Qci+Qbv已经实现时间准入、插帧过滤、Flow Meter式突发限制、Deadline和MaxQueueDelay策略。
- 当前Clipped-Qci准入模块仍位于发送端应用边界，还不是独立的交换机入口模块。
- 当前实验没有加入独立的多跳时钟偏差、传播时延和多随机种子重复。

### 8. 组会结论

1. Qbv-only能保证合法出口窗口，但不知道帧是否过期、重复、缺失或属于异常突发。
2. Full-Qci+Qbv能解决流识别、入口门控和速率监管问题，但标准Qci不能自动完成序号连续性和逐帧Deadline判断。
3. Clipped-Qci+Qbv通过时间戳、周期、序号、Deadline和MaxQueueDelay补充了裁剪流门控表后的时间状态判断，更适合控制最大时延和保证新鲜帧优先。
4. 三种方案都不能增加链路容量，也不能恢复已经丢失的帧。差异主要体现在异常帧进入网络的位置、是否能够识别业务时效，以及是否能够在队列溢出前主动丢弃。
5. 下一步重点是把Clipped-Qci准入模块移动到交换机入口，加入ReorderTimeout、多跳同步误差和多随机种子重复实验。
